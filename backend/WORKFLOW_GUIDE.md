# 🚀 Rust Workflow dengan SeaORM & Rayon - Panduan Implementasi

## 📋 Overview

Dokumentasi lengkap untuk implementasi workflow backend dengan pendekatan **functional programming**, **immutability**, dan **parallel processing**.

### Tech Stack
- **SeaORM**: Database ORM dengan type safety
- **Rayon**: Parallel data processing
- **Chrono**: Date & time management
- **Axum**: Web framework

### Design Principles
1. ✅ **Vec Boundary Policy**: Vec HANYA dari database query
2. ✅ **Logic Constraint**: Slice-based processing (no Vec mutation)
3. ✅ **Enum-First Design**: Gunakan Enum untuk semua state/hasil
4. ✅ **Strict Immutability**: No `mut` keyword dalam logic
5. ✅ **Rayon Integration**: Parallel processing untuk performance

### Phase 3: Implement Service Layer

**File:** `src/services/workflow_service.rs` (sudah dibuat dengan template)

**Key Components:**

```rust
pub enum StatusJadwal {
    Mendesak { jadwal_id, waktu_mulai, selisih_menit },
    Aman { jadwal_id, waktu_mulai },
    Selesai { jadwal_id, waktu_selesai },
}

    JadwalTerdekat(StatusJadwal),
    TidakAdaJadwal,
    Error(String),

```

2. **Database Layer** (Vec Boundary)
```rust
pub async fn fetch_jadwal_dari_db(&self) -> Result<Vec<Jadwal>, DbErr> {
    // ✅ Vec HANYA di sini
    JadwalEntity::find().all(&self.db).await
}
```

3. **Processing Layer** (Immutable)
```rust
pub fn cari_jadwal_terdekat(jadwal_slice: &[Jadwal]) -> HasilAnalisa {
    // ✅ Terima slice, bukan Vec
    // ✅ No mut keyword
    // ✅ Rayon par_iter()
    jadwal_slice
        .par_iter()
        .filter(|j| j.start_time > Utc::now())
        .min_by_key(|j| (j.start_time - Utc::now()).num_seconds())
    // ... convert to enum
}
```

- Generate entities dengan sea-orm-cli
- Check path di `entities/mod.rs`

### Issue 2: "No method par_iter"
```
Error: no method named `par_iter` found
```
**Solution:**
```rust
use rayon::prelude::*;  // ← Tambahkan ini
```

### Issue 3: Type mismatch DateTime
```
Error: expected DateTime<Utc>, found NaiveDateTime
```
**Solution:**
- Gunakan `with-chrono` feature di sea-orm
- Ensure database column type: `TIMESTAMP WITH TIME ZONE`

### Issue 4: Multiple states in Axum
```
Error: cannot merge routers with different state types
```
**Solution:** Lihat `main_baru.rs` untuk pattern multiple states

## 📖 Design Pattern Explanations

### 1. Vec Boundary Policy

**Problem:** Vec mutation scattered everywhere, hard to track

**Solution:**
```rust
// ❌ BAD: Vec mutation di logic
fn process(mut data: Vec<Item>) -> Vec<Item> {
    data.push(new_item);  // Mutation!
    data
}

// ✅ GOOD: Vec hanya dari DB, slice untuk logic
async fn workflow() -> Result {
    let vec = db.query().await?;      // Vec from DB
    let slice = vec.as_slice();        // Convert to slice
    let result = process(slice);       // Process immutably
    result
}
```

### 2. Enum-First Design

**Problem:** Unclear return types, tuple hell

**Solution:**
```rust
// ❌ BAD: Opaque tuple
fn analyze() -> (i32, String, bool) { ... }

// ✅ GOOD: Self-documenting enum
enum HasilAnalisa {
    JadwalTerdekat(StatusJadwal),
    TidakAdaJadwal,
    Error(String),
}
```

### 3. Strict Immutability

**Problem:** Mutation bugs, race conditions

**Solution:**
```rust
// ❌ BAD: Mutable state
fn filter(data: &mut Vec<Item>) {
    data.retain(|x| x.is_valid());
}

// ✅ GOOD: Functional transformation
fn filter(data: &[Item]) -> Vec<&Item> {
    data.iter().filter(|x| x.is_valid()).collect()
}
```
